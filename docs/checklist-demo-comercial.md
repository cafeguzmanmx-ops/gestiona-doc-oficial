# Checklist para demo comercial de Gestiona Doc

## Antes de la demo

- Confirmar que Railway tenga activos los servicios de API, Web y PostgreSQL.
- Confirmar que la variable `VITE_API_URL` apunte a la API pública.
- Crear el `SUPER_ADMIN`.
- Crear el municipio demo desde el panel SaaS o desde el script.
- Probar login con usuario administrador demo.
- Revisar que existan oficios en distintos estatus.
- Probar que el dashboard cargue indicadores.
- Probar que los reportes exporten Excel/PDF.

## Guion sugerido de demostración

1. Explicar el problema: oficios dispersos en papel, Excel, correo y WhatsApp.
2. Mostrar landing y propuesta de valor.
3. Entrar como administrador municipal.
4. Mostrar organigrama y usuarios.
5. Registrar un oficio recibido.
6. Adjuntar PDF.
7. Turnar a un área responsable.
8. Entrar al detalle del oficio.
9. Agregar seguimiento.
10. Mostrar alertas internas.
11. Cerrar oficio.
12. Mostrar dashboard.
13. Exportar reporte.
14. Entrar como `SUPER_ADMIN` y mostrar panel SaaS.
15. Mostrar solicitudes de demo y control de suscripciones.

## Mensaje comercial recomendado

Gestiona Doc no busca sustituir todo el expediente electrónico municipal en su primera versión. Su valor inicial es resolver el control de correspondencia oficial: saber qué entró, quién lo tiene, cuándo vence, qué avance lleva y cómo se reporta.

## Cierre sugerido

Ofrecer piloto anual con acompañamiento de implementación y configuración inicial del organigrama municipal.
